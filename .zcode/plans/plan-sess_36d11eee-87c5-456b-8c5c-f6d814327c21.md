## Zoomable Canvas + Movable Nodes — Implementation Plan

Make the `/characters/` chart a real graph explorer: wheel/pinch zoom toward the cursor, drag-to-pan, drag-to-move nodes, a "Copy layout" export that writes `layoutOverrides` JSON, and layout math that scales as the roster grows. All in `RelationshipMap.astro`'s existing inline-script pattern — no libraries, no framework components.

### 1. Pan & zoom (all in `src/components/RelationshipMap.astro`)

- **World layer**: wrap the `<svg>` + node buttons in a new `.relmap-world` div inside `.relmap-stage`. Pan/zoom is one CSS `transform: translate(...) scale(...)` on that layer (`transform-origin: 0 0`). The stage keeps its aspect-ratio, `container-type`, and cqw sizing, so the dossier panel's squeeze-rescaling keeps working unchanged.
- **Move the tooltip out**: `.relmap-tip` becomes a sibling of the world layer (positioned in stage screen coords) so it doesn't scale or drift with zoom. Its clamping math against `stage.getBoundingClientRect()` already works as-is.
- **Initial state**: scale 1, translate 0 — fit-to-view on load, exactly today's appearance. On load with a `#char-` hash, pan (no forced zoom) so the selected node is centered.
- **Zoom limits**: 0.4×–4×, wheel zooms toward the cursor (`z *= Math.exp(-deltaY * 0.0015)`, `preventDefault` on the stage only). Pinch-zoom + one-finger pan via pointer events with `touch-action: none` on the stage; the stage already fits the viewport width, so this doesn't trap page scroll in practice.
- **Controls**: a small `+ / − / ⤢ reset` button group overlaid top-left of the frame (mono styling, `aria-label`s, 44px targets on coarse pointers). Reset returns to fit. Deep links / chip navigation pan to center the target node.
- **Click-vs-drag disambiguation**: a pointerdown→pointerup with <5px movement is a click (existing deselect/toggle behavior preserved); anything more is a pan and swallows the click.
- **Edge strokes**: `vector-effect="non-scaling-stroke"` keeps lines and the 14px hover hit-lines constant width on screen through zoom (verified behavior for CSS ancestor transforms; if a browser disagrees, drop the attribute — strokes scaling with zoom is acceptable).

### 2. Movable nodes

- **Pointer events on nodes**: pointerdown on a node starts a potential drag with `setPointerCapture`; movement >5px converts to drag (translate the node's `left/top` %), pointerup without it falls through to the existing click handler. A dragged node gets elevated `z-index` and a subtle grab cursor; the cursor tooltip and hover states are suppressed mid-drag.
- **Live edge redraw**: dragged node's connected `<line>`s update `x1/y1/x2/y2` in viewBox units (`deltaPx / worldRect.width * designWidth`). The `data-from`/`data-to` attributes on edges already give the adjacency lookup.
- **Bounds**: dragged positions clamp to the design box margins (same 70/64px insets the layout uses), so nodes can't be flung outside the frame.
- **Keyboard nudge**: the selected node moves with arrow keys (1 design-unit steps, Shift = 10) and announces via the existing `role="status"` strip. Cheap, and keeps the feature non-mouse-only.
- **Export**: a "Copy layout" button (next to the zoom controls) writes `{ "id": { x, y }, ... }` for every node whose position differs from the build default, as `layoutOverrides`-shaped JSON with 1-decimal rounding, to the clipboard, then confirms in the status strip ("Layout copied — paste into layoutOverrides in src/data/characters.ts"). Pasting into the existing `layoutOverrides` export makes the arrangement the build-time default for everyone; empty overrides restore the pure computed layout.

### 3. Scale-readiness for a growing roster (`src/lib/diagramLayout.ts`)

Small, roster-aware constants so the current layout math keeps working at 60–100 nodes without redesign:
- Design box grows with the roster: `H = 800 + 220 × max(0, figures − 28) / 10`-style linear headroom (exact formula at implementation, derived so MIN_DISTANCE clearance holds), aspect clamped to a sane band.
- Ring/fan radii scale gently with node count (`rx/ry` already relative to W/H; fan radii get a `1 + n/40` multiplier) so fans don't collide as Earthians accumulate figures.
- Everything else (relaxation, pinned Earthians, overrides) untouched — still deterministic, still build-time; 100 nodes is trivially cheap.
